> **打破傳統清單，用色彩平衡你的工作量。** > 這是一個基於 C++ 與 SFML 開發的動態任務排程系統，旨在將「時間壓力」視覺化，協助使用者自動化分配每日工作建議。

---

## Proposal Report

### 動機與目標
* **動機**：解決傳統行事曆僅能「記錄」而無法「平衡負載」的問題，防止工作在截止日前夕堆積。
* **目標**：透過彩色方塊視覺化任務，結合緊迫性與工時，自動生成每日工作量建議。

### 競品比較
| 軟體名稱 | 主要功能 | Task Palette 優勢 |
| :--- | :--- | :--- |
| **Google Calendar** | 傳統格子式日曆，側重行程記錄 | **視覺化排程**：以彩色方塊直觀呈現剩餘工時。 |
| **Microsoft To Do** | 條列式清單，手動排序 | **智能分配**：自動計算並建議今日最優工作量。 |
| **Notion** | 強大的資料庫與筆記功能 | **輕量與專注**：專注時間壓力，無須複雜設定。 |

### 預期功能
* **動態時間權重計算**：系統能根據截止日期與剩餘天數，自動計算每項任務的緊急程度。
* **每日產能動態調整**：使用者可自訂每日最大工作時數（Daily Capacity），系統依此分配當日建議工作量。
* **色彩視覺化回饋**：利用色彩（紅、黃、灰等）直觀呈現任務狀態，達到壓力預警效果。
* **資料持久化**：重啟程式時能自動讀取與儲存先前的任務清單。

### 使用技術
* **Core**: C++ 20
* **Graphics**: SFML 3.0
* **Build Tool**: VS Code + MSYS2

### Prototype預計可驗證內容
* **核心排程邏輯可行性**：驗證基於截止日期的分配演算法是否能正確算出「每日建議工時」。
* **GUI 互動基本架構**：驗證 SFML 視窗與事件處理（如點擊、輸入）能否流暢運作不卡頓。
* **CSV 檔案正確讀寫**：驗證底層資料結構（Vector）與外部檔案的轉換是否會產生資料遺失。

## Prototype Report

### 目前進度
* **互動式 UI**：實作 SFML 視窗、任務列表、編輯選單與輸入對話框。
* **動態排程演算法**：初步實現基於「建議每日工時」的優先權算法。
* **資料持久化**：支援 CSV 檔案存取，包含任務資料與 `Daily Capacity` 設定。
* **狀態辨識系統**：自動標註顏色（今日截止、明日預告、過期）。

### 遇到的困難與對策
1.  **效能分析規模**：
    * *困難*：小量任務下 $O(N \log N)$ 差異不明顯。
    * *對策*：預計撰寫測試腳本模擬 1,000 ~ 10,000 筆任務，驗證效能臨界點。
2.  **動態權重重新排序**：
    * *困難*：權重隨日期流逝每日變動，需頻繁刷新。
    * *對策*：評估 `std::vector` 的連續記憶體優勢與 `std::priority_queue` 重建的開銷差異。
3.  **邊界計算處理**：
    * *困難*：今日截止任務會導致分母為零。
    * *對策*：實作條件分支，將今日截止任務設為「絕對優先」並分配全部剩餘工時。

## Final Report

### 專案說明

#### 專案成果與實作邏輯

本系統成功以 C++20 與 SFML 3.0 打造出一個具備互動性的「智慧型個人產能調色盤」。我們擺脫了傳統行事曆的靜態記錄模式，落實動態排程與視覺化壓力預警。核心技術實作包含以下三大亮點：

##### 1. 動態權重分數公式 Priority Score
為了精準量化任務的急迫性，系統針對每項任務計算其動態權重分數：

$$Priority\ Score = \frac{100}{Hours\ Left} + Unfinished\ Time \times 2.0$$

* **時間敏感項（左側）**：隨著截止時間（`Hours Left`）逐步逼近，分數將呈現指數級暴增。
* **工作量加權（右側）**：結合任務的剩餘總工時（`Unfinished Time`），確保龐大任務不會被無限期延後。

##### 2. 智慧超載偵測 Overload Detection
演算法內部會動態累加當日所有必須執行的任務工時。一旦總工時超出使用者自訂的每日產能上限，便會觸發預警：

$$\sum Task_{Today} \cdot Unfinished\ Time > dailyCapacity$$

##### 3. 雙層動態排序架構
系統採用雙層排序邏輯，在每秒 60 幀（60 FPS）的渲染迴圈中即時重組畫面：
* **第一層：層級排序 (Rank Sorting)**
    * `Rank 0`（今日截止）：第一優先，強制置頂。
    * `Rank 1`（明日截止）：第二優先，緊隨其後。
    * `Rank 2`（未來任務）：正常依時間序排列。
    * `Rank 3`（過期任務）：強制墊底，避免干擾當日專注度。
* **第二層：權重排序 (Weight Sorting)**：若多個任務處於相同 Rank 階層，系統會進一步比對上述的 `Priority Score`，精準微調前後順序。

---

#### 底層資料結構比較與選擇

在架構設計初期，我們針對核心容器 `std::vector` 與理論上流暢的 `std::priority_queue` 進行了技術抉擇評估：

| 操作與特性 | `std::vector` + `std::sort` (目前採用) | `std::priority_queue` (動態優先隊列) |
| :--- | :--- | :--- |
| **底層結構** | 連續記憶體陣列 (Dynamic Array) | 二元堆積 (Binary Heap) |
| **隨機存取 (`[i]`)** | **$O(1)$（極快，SFML 渲染與滑鼠點擊必備）** | 不支援（只能看 Top，無法點擊特定任務） |
| **單次排序複雜度** | $O(N \log N)$ | $O(\log N)$（僅限插入/刪除） |
| **持久化（轉 CSV）** | **$O(N)$ 循序遍歷，順序完全固定** | 必須不斷 Pop，會破壞原本的隊列結構 |

**核心工程決策結論：**
雖然 `priority_queue` 在動態維護上具有優異的理論複雜度，但**不支援隨機存取**。考慮到系統前端需要循序遍歷所有任務以渲染進度條，且使用者需要透過滑鼠點擊任意任務來觸發編輯選單），具備 $O(1)$ 隨機存取特性的 `std::vector` 成為了較佳解。在個人小規模任務（$N < 100$）下，Vector 的 CPU 快取友善性（Cache Friendly）更帶來了極佳的實質效能。

### 使用說明

當使用者啟動系統後，主介面將完美整合時間排程與壓力視覺化回饋：

#### 1. 基礎操作流程
* **即時動態重算**：系統在每次啟動時，都會根據當下系統時間自動重新排序，確保時間線永遠最新。
* **自訂每日工時**：右上角可自由設定當天預計能工作的總時數（例如：`Work Hours: 8h`）。
* **新增與編輯任務**：點擊右下角的 **`+` 藍色懸浮按鈕** 可喚出輸入對話框；點擊任何現有任務卡片即可進入獨立編輯選單。

#### 2. 壓力視覺化與狀態辨識
系統依據任務的緊急程度，自動賦予卡片不同的莫蘭迪色燈號，達到直觀的減壓與警示效果：
* 🟥 **紅色卡片 (DUE TODAY!)**：今日截止任務，絕對優先置頂。
* 🟪 **粉紅卡片 (DUE TOMORROW!)**：明日截止任務，次高優先級。
* 🟦 **藍色卡片**：未來任務，顯示剩餘天數（如 `5 days left`）。
* ⬛ **灰色卡片**：過期未完成任務，強制墊底，不佔用今日工時與專注版面。
* 🟩 **綠色進度條**：每張卡片下方附有綠色動態進度條，清晰顯示該任務目前的完成比例。
* 🟨 **黃色超載預警 (! Overload: Need Xh.)**：當今日必做任務的總工時超出使用者設定的 `Work Hours` 時，頂端會即時跳出黃色警示，提醒使用者重新調整今日規劃，防止崩潰。


### 反思與精進

在本次期末專案的完整開發流程中，不僅成功驗證了核心動態排程演算法在 SFML 前端渲染上的可行性，也在 C++ 底層容器抉擇中進行了深入的效能評估。然而，從軟體工程與系統工程的視角出發，本系統仍有以下可持續優化的方向：

#### 1. 代碼解耦與模組化設計 (Architecture Decoupling)
目前系統的動態排序演算法與 SFML 的每影格事件迴圈結合得較為緊密。雖然透過 `std::vector` 與自訂 Lambda 比較器達到了流暢的互動效能，但未來精進的首要目標是將系統徹底落實 **MVC（Model-View-Controller）架構**。將 `Scheduler` 的核心計算邏輯與 `RenderWindow` 的畫面繪製完全分離，以提升系統的單元測試（Unit Test）覆蓋率與程式碼可維護性。

#### 2. 時間計算的極端邊界處理 (Edge Case Robustness)
目前系統在處理「今日截止」的任務時，已透過條件分支成功避免了分母為零的邏輯崩潰。然而，針對跨時區、日光節約時間（DST）或使用者手動修改系統時鐘等極端硬體情境，底層時間戳記的解析仍有優化空間。未來預計引入 C++20 的 `<chrono>` 庫進行更精準的時區安全（Timezone-safe）運算。

#### 3. 用戶輸入的攔截與異常防禦 (Defensive Programming)
在現階段的任務建立選單中，當使用者輸入不符合規範的日期格式或極端龐大的工時數值時，系統主要是透過簡單的條件語句進行攔截。為了打造更強健的工業級軟體，未來計畫實作**正規表示法（std::regex）**進行更嚴格的輸入驗證，並全面導入 C++ 的異常處理機制（`try-catch`），確保任何異常輸入都不會引發程式閃退。

#### 4. 長期擴充：產能統計與數據持久化升級
目前資料持久化採用輕量化的 CSV 檔案讀寫。隨著系統未來走向多用戶或任務標籤（學業、生活、工作）的分類篩選，CSV 的循序讀取效能將成為瓶頸。未來規劃升級為 **SQLite 輕量化資料庫**，並配合每週任務達成率的視覺化圖表，為用戶提供更長期的個人產能大數據分析。

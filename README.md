> **打破傳統清單，用色彩平衡你的工作量。** > 這是一個基於 C++ 與 SFML 開發的動態任務排程系統，旨在將「時間壓力」視覺化，協助使用者自動化分配每日工作建議。

---

## Proposal Report

### 動機與目標
* **動機**：解決傳統行事曆僅能「記錄」而無法「平衡負載」的問題，防止工作在截止日前夕堆積。
* **目標**：透過彩色方塊視覺化任務，結合緊迫性與工時，自動生成每日工作量建議。

### 競品比較
| 軟體名稱 | 主要功能 | Task Palette 優勢 |
| :--- | :--- | :--- |
| **Google Calendar** | 傳統格子式日曆，側重行程記錄 | **視覺化排程**：以彩色方塊直觀呈現剩餘工時。 |
| **Microsoft To Do** | 條列式清單，手動排序 | **智能分配**：自動計算並建議今日最優工作量。 |
| **Notion** | 強大的資料庫與筆記功能 | **輕量與專注**：專注時間壓力，無須複雜設定。 |

### 預期功能
* **動態時間權重計算**：系統能根據截止日期與剩餘天數，自動計算每項任務的緊急程度。
* **每日產能動態調整**：使用者可自訂每日最大工作時數（Daily Capacity），系統依此分配當日建議工作量。
* **色彩視覺化回饋**：利用色彩（紅、黃、灰等）直觀呈現任務狀態，達到壓力預警效果。
* **資料持久化**：重啟程式時能自動讀取與儲存先前的任務清單。

### 使用技術
* **Core**: C++ 20
* **Graphics**: SFML 3.0
* **Build Tool**: VS Code + MSYS2

### Prototype預計可驗證內容
* **核心排程邏輯可行性**：驗證基於截止日期的分配演算法是否能正確算出「每日建議工時」。
* **GUI 互動基本架構**：驗證 SFML 視窗與事件處理（如點擊、輸入）能否流暢運作不卡頓。
* **CSV 檔案正確讀寫**：驗證底層資料結構（Vector）與外部檔案的轉換是否會產生資料遺失。

## Prototype Report

### 目前進度
* **互動式 UI**：實作 SFML 視窗、任務列表、編輯選單與輸入對話框。
* **動態排程演算法**：初步實現基於「建議每日工時」的優先權算法。
* **資料持久化**：支援 CSV 檔案存取，包含任務資料與 `Daily Capacity` 設定。
* **狀態辨識系統**：自動標註顏色（今日截止、明日預告、過期）。

### 遇到的困難與對策
1.  **效能分析規模**：
    * *困難*：小量任務下 $O(N \log N)$ 差異不明顯。
    * *對策*：預計撰寫測試腳本模擬 1,000 ~ 10,000 筆任務，驗證效能臨界點。
2.  **動態權重重新排序**：
    * *困難*：權重隨日期流逝每日變動，需頻繁刷新。
    * *對策*：評估 `std::vector` 的連續記憶體優勢與 `std::priority_queue` 重建的開銷差異。
3.  **邊界計算處理**：
    * *困難*：今日截止任務會導致分母為零。
    * *對策*：實作條件分支，將今日截止任務設為「絕對優先」並分配全部剩餘工時。

## 下一步計畫

### 短期目標
-  **工時預警系統**：根據緊急程度顯示不同顏色（深紅色、粉紅色、藍色、灰色）。
-  **邏輯解耦**：將排程演算法完整封裝至 `Scheduler` 類別。

### 中期目標
-  **任務標籤**：支援分類篩選（學業、生活、工作）。
-  **正規表示法**：強化日期與時數輸入的攔截檢查。

### 長期目標 
-  **遊戲化**：實作 XP 經驗值系統與等級制度，加入逾期扣除體力機制。
-  **產能數據統計**：實作每週任務達成率的視覺化圖表。
